# 0.5.3 安装失败与目录切换修复

用户在 Win11 覆盖安装 0.5.2 时遇到 `Installation failed ... Exit code: 1`，
随后反馈旧服务器可能没有完全退出。此退出码仅表示安装子进程失败；尚未取得该服务器的
底层错误日志，不能断言其实际触发原因。

## 已确认的问题与修改

在本机用文件句柄禁止删除/重命名一个旧程序文件，复现了 Windows PowerShell 5.1
`Move-Item` 的部分移动：前面的文件已进入 backup，遇到被占用的文件才失败，旧 app 目录不再完整。
原弹窗因此不能保证“旧程序已保留”。本次合成业务数据文件未受影响。

安装器现在使用同一父目录下的 `.NET Directory.Move` 重命名旧程序、发布新程序和回滚，
避免逐文件移动。发布后的清理独立于回滚：旧目录先改为 `retired-` 前缀再清理，
清理失败会保留新版并提示残留位置，不会把已部分删除的旧目录当作可恢复备份。
回滚失败明确报告保留的目录和错误，不再静默忽略。

服务器 Setup 新增独立的 PowerShell 输出捕获入口，失败时保留经脱敏的 stdout/stderr，
弹窗展示底层原因与日志位置。日志固定在当前 Windows 账号的
`%LOCALAPPDATA%\GWAPDebugServer\install-logs`，不依赖业务数据的自定义目录。
安装流程仍为先解包、完整校验、隔离自检，再切换程序；不会在安装过程中启动服务器或模型。

## 用户处理方式

无需卸载。先在旧服务器窗口按 `Ctrl+C` 并等待退出；如果仍有来自 GWAP 服务器程序目录
的 Python、llama-server 或 Caddy 进程，只结束这些残留进程。不要结束其他软件的同名进程。
业务数据、数据库和安装失败留下的 backup 目录不要删除。保留已有业务备份，然后用原
Windows 账号重新运行完整的服务器 EXE，成功后再启动服务器。

本次安装器修复不改变应用、数据库迁移、模型、管理员密钥或内置六文件 Skill。
配套分机继续使用字节相同的 0.5.0 ZIP。API/MCP 与 `workflow/skill.yaml` 无变更。

## 新增验证与边界

- 原版 0.5.2：实际发布 EXE 的本机新装、包内发布脚本的隔离新装成功。
  这两项为排查本次失败新做的安装路径验证，不等同于用户服务器的升级成功。
- 修复后的 Windows PowerShell 5.1 新增三项故障检查通过：锁定旧文件时整个旧目录保留；
  清理 retired 目录中断时新版保留；发布后创建快捷方式失败时整目录恢复旧版。
- 日志入口与最终新 EXE 验证、交付状态以 [VALIDATION.md](../VALIDATION.md) 为准。

仅执行本次安装故障的定向检查。既有网页、API/CLI、GGUF 与知识/管理员恢复证据复用，
不重跑成功的历史回归、Full/External 或手动 CI。未声称真实断电、用户公司服务器或独立干净机器验收完成。
