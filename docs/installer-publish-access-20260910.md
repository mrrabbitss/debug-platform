# 0.5.4 发布新目录访问被拒绝：公司日志定位与 0.5.5 加固

用户提供了公司服务器的安装日志。本文仅记录脱敏后的结论，不将日志原文、账号或公司路径加入 Git。

日志显示完整组件、SHA-256、后端/前端、隔离 Python 和 GGUF 契约校验均通过。旧程序目录成功保留，随后 `Directory.Move(staging, destination)` 返回访问被拒绝，安装器记录旧程序目录已完整恢复。因此可确认失败阶段是新程序目录发布；尚不能从日志确定句柄持有者或区分短暂占用与持续访问策略。该日志未显示数据库迁移或业务数据修改。

## 0.5.5 修改

同父目录的整目录重命名保持原子性。仅在 Windows 错误 5/32/33、源目录仍存在且目标不存在时，每 500ms 重试，最长约 15 秒。恢复、保留、发布及回滚均使用同一规则。目标已存在、源丢失或其他错误立即失败，不合并目录、不强杀进程、不修改权限、不绕过安全软件。

持续失败时输出具体阶段、Windows 错误码、源/目标路径与原始错误，并沿用回滚。旧版备份清理失败仍不撤回新版。

PowerShell 子进程捕获原始异常，使用独立错误标识输出，弹窗优先采用这条原因；避免之前倒序选中 `FullyQualifiedErrorId : IOException` 而遮住原因。完整日志继续保存在服务器安装账号的 `%LOCALAPPDATA%\GWAPDebugServer\install-logs`。

## 新增验证与边界

Windows PowerShell 5.1 三项新增验证通过：发布时锁住新 staging 文件，1.2 秒释放后重试成功；持续锁定超过重试窗口后旧程序完整恢复、合成业务数据不变；真实 PowerShell IOException 的摘要保留原因并含错误位置，排除无用错误标识。

应用、模型、Skill 和分机继续沿用 0.5.4/0.5.0 的既有验证，不重复历史已通过回归或模型调用。打包及交付结果见 VALIDATION.md。公司服务器尚未执行此修复；持续权限限制需要根据新日志由公司环境侧排查，不能保证单靠重试解决。
