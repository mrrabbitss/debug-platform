# 从 release 分支准备服务器

当前服务器已有 `artifacts\lan\server-pilot-20260907` 时，直接按[服务器使用指南](服务器使用指南.md)启动。
下面只用于新克隆的仓库，不要在正在使用的服务器目录中重新构建。

## 生成服务器运行目录

在 Windows 11 上准备 Python 3.12、Node.js 22 和 Git。首次构建需要联网下载依赖、运行时和模型。
在仓库根目录的 PowerShell 中依次执行；任一步报错就先停止处理：

```powershell
.\scripts\bootstrap_local.bat --no-pause
python -B scripts/model-runtime/prepare_assets.py --all
.\scripts\build_windows_gguf_installer.bat -Version 0.3.1 -SkipSetupExe -OutputRoot artifacts/installer/release-build
.\.venv\Scripts\python.exe -B scripts/build_windows_server.py --portable artifacts/installer/release-build/staging/debug-platform-windows-x64 --output artifacts/lan/server-pilot-20260907
```

构建命令只生成文件，不安装服务器。完成后双击 `scripts\start_lan_server.bat`。
输出目录必须不存在；已有服务器请保留原程序和数据，不要直接覆盖。

模型文件和 Python/Node 运行时不存入 Git。下载地址、版本及哈希由
`scripts/model-runtime/model-assets.json`、`deploy/windows-server/runtime.lock.json` 和现有依赖锁文件固定。
详细构建说明见 [GGUF 构建文档](windows-offline-gguf-installer.md)。

## 分机文件

现成分机 ZIP 和两份使用指南在 `deploy/releases/20260907`。分机不需要构建代码。
要重新生成分机包，在仓库根目录执行：

```powershell
.\.venv\Scripts\python.exe -B scripts/build_windows_client.py --output artifacts/lan/client-rebuild
```

输出目录中的 ZIP 可直接分发。服务器地址、证书和每人的访问令牌在部署后另行提供。
