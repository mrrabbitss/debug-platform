# 旧库升级后的内置组网 Skill 导入修复

用户确认旧实例显示“已保留现有知识和 Skill”。该状态表示自动初始化检测到旧知识、草稿或历史记录后跳过导入，不能作为六文件已经入库的证明。0.5.3 安装载荷中的原 ZIP 和六份文件完整；缺口在旧数据库的显式导入入口。

## 0.5.4 行为

管理员和专家在左侧“知识库管理”顶部点击“导入内置组网 Skill”，直接核对服务器随包的总领 SKILL.md 和五份参考文件。服务端选择并校验原 ZIP、完整文件哈希及当前数据库路径，网页不需重新上传或填写目录。预览展示用途、冲突和根 Skill 平台适配差异。

仅完整六文件全部缺失时允许确认。已有同名、已删除、人工修改或草稿冲突会阻止此入口，交由现有知识管理核对；不覆盖、不重复创建、不复活已删除文件。已经完整存在时提示无需导入。现有案例、报告、知识、Skill、草稿、全局记忆和已绑定报告模板保留。

确认绑定原包哈希、预览哈希和当前库版本。SQLite 一致备份、原文件及审批记录持久保存，审批和后台任务同事务落库。后台以保留的有效共享知识加六份新 Skill 构建完整向量和图谱代际，成功后一次发布；失败不切换旧代际。重试复用审批，页面刷新后可查询同一任务。沿用当前 Embedding，外部 Embedding 必须确认内容出站；不调用诊断 Chat 模型。

API 新增 `/api/v1/workbench/bundled-skill/preview`、`/confirm` 和 `/{operation_id}`，仅 ADMIN/EXPERT。数据库迁移仍为 0025，分机协议不变。原高级清空重置功能保持独立。
