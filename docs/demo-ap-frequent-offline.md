# AP 频繁离线联合诊断演示

这套样本只包含合成设备名、文档地址段 IP 和本地管理 MAC，不含公司日志或凭据。它用三次
可重复故障周期展示 AP 侧 UDM 进程/监听端口/Advertise 异常，随后 GW 侧心跳超时、控制点判
离线、拓扑删除和恢复的完整链路。仓库同时保存此前通过 `https://wawapii.com` 成功完成的
真实 GLM-5.2 运行结果；这是脱敏后的历史快照，不是手工编造的确定性结论。

## 真实模型/本地回归脚本

先启动平台：

```bat
scripts\start_local.bat
```

该命令会持续占用启动窗口。看到前后端就绪后保持该窗口运行，另开一个 CMD 进入同一项目目录，
再执行下面的回归命令。

使用已配置的 Chat 模型完成智能日志筛查和最多二十轮综合诊断时，必须显式同意发送这组
合成日志：

```bat
scripts\seed_ap_offline_demo.bat --approve-model-egress
```

慢速内网模型可单独提高每个后台任务的等待上限（默认 1,200 秒）：

```bat
scripts\seed_ap_offline_demo.bat --approve-model-egress --job-timeout-seconds 1800
```

`--job-timeout-seconds` 的有效范围是 30 至 14,400 秒。平台不在默认
`http://127.0.0.1:8000/api/v1` 时，可追加 `--api-root <API地址>`。

不调用外部模型，仅验证解析、领域事件和确定性故障树证据账本时：

```bat
scripts\seed_ap_offline_demo.bat --local-only
```

该 seed 脚本创建的是普通回归案例，不匹配上文保留演示案例的公开方法契约。它会创建案例、
分别标注主 GW/从 AP、上传并解析两份日志；模型模式还会逐份完成智能日志
筛查，最后运行综合诊断并打印案例链接、故障树覆盖、关键根因状态、最终合成模式和假设数量。
创建案例前会先确认根目录存在 Git 忽略的 `故障树.md`/`日志分析.md`，或知识库中已有审核发布的
等价角色文档；缺少方法时立即退出，不会留下半成品案例或产生模型费用。
模型模式还要求 LLM 规划确实通过、日志筛查至少选择一个有效 Pattern 或精确关键词，并在
1 至 20 轮内原生发起有命中的 `search_log`。后端会对首批搜索证据执行一次标记为
`POLICY_EVIDENCE_HYDRATION` 的有界 `get_evidence` 只读取回，并校验读取 ID 来自前置模型搜索；
该策略调用不会冒充模型成功。模型还必须自行把故障树和日志分析方法都判定为相关。
它不仅检查 27/27 完成率，还会阻断根因场景、四类跨设备
假设、UDN/MAC 本地比较、方法阅读、证据类型或报告文件行号错误；报告出现内部证据主键也会
直接失败。
私有根目录 `故障树.md`、
`日志分析.md` 或知识库中等价的已发布方法仍是该 seed 路径的方法来源；脚本不会复制或提交它们。

## 预期诊断

- 拓扑确认 AP1 直连主 GW，三次离线均为同一 AP；
- `REACHABLE` 和链路 Up 是物理链路的正向反证；
- AP 侧 UDM 进程异常、监听端口失败和 Advertise 发送失败构成起点；
- GW 侧随后出现 `iAdvrTimeOut`、`CtrlPointVerify`、`Status=[0]` 和拓扑删除；
- 只有 `curTime - lastEventTime > iAdvrTimeOut` 时才算心跳超时；端口恢复、心跳发送成功或未
  超过阈值的计时记录不得当作故障支持证据；
- `TestLinkOK failed` 单独出现时只能说明链路检测失败，不能同时断言物理链路和网络传输两个
  根因；只有 `carrier lost`/`no carrier` 或 UDP 丢包/SSDP 多播阻断等明确证据才进入对应分支；
- 故障树应支持“UDM 协议栈问题”，排除“物理链路问题”，将缺少抓包反证的“网络传输问题”
  保持为证据不足；
- 所有支持/排除结论必须显示真实的“文件名 - 行号”，不得把内部证据主键展示给用户。
- 模型补充关键词和第一层 Pattern 选择都会过滤 `Start`、`FAILED`、`ERROR`、`offline` 等
  过宽单词；这些方法规则仍在第二层完整扫描，避免普通命令头、非目标错误或字符串子串被
  错误提升到“LLM 判断相关”。

即使模型输出漏掉相关方法的 `check`，或把无证据结论写成 `SUPPORTED/EXCLUDED`，后端也只会
补齐只读检查与检索绑定，并把无有效证据的结论降级成“证据不足”。若模型仍不合规或超时，
确定性方法证据扫描会为全部故障树节点给出支持、排除或证据不足终态，保留失败原因而不返回
空诊断。
