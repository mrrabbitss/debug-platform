# 服务器使用指南

本次内网专用安装包已包含 Python、完整 Embedding/Reranker、HTTPS 网关和服务器地址。

## 安装和启动

1. 如果旧服务器正在运行，先按 `Ctrl+C` 停止；已有业务数据先备份。
2. 双击 `GWAP-Debug-Server-Setup-0.4.0-x64.exe` 安装。升级首次启动会迁移数据库，请等待 `READY`。
3. 双击桌面“GWAP 服务器”，等待 `READY`。首次地址已预置，之后沿用保存的配置。
4. 使用期间保持窗口打开，并关闭电脑自动睡眠；停止时按 `Ctrl+C` 等待退出。

安装包不会修改 Windows 网卡的 IP、子网掩码或网关。首次安装默认 HTTPS 端口为 `8443`；升级沿用已保存的端口。

### 上传知识时报 Embedding 输入过长

0.3.3 原安装包遇到较长 Markdown 时，可能报 `input ... is too large ... physical batch size`。
0.4.0 已包含这项修复。升级后在网页“系统设置 → 模型与索引”重建向量索引，等待任务成功，再检查此前的草稿。
如果失败的上传没有留下文档，再重新上传；已有文档无需重复上传。

### 放行 HTTPS 端口

如分机无法访问，在管理员 PowerShell 中放行端口：

```powershell
New-NetFirewallRule -DisplayName "GWAP HTTPS" -Direction Inbound -Action Allow -Protocol TCP -LocalPort 8443 -Profile Domain,Private -RemoteAddress LocalSubnet
```

该规则允许同一子网；其他网段需另行放行。已有规则时无需重复添加。

## 同事接入

把配套的分机 ZIP 发给同事。服务器先保持运行，同事安装时输入“一位小写字母＋八位数字”的个人识别码即可。
账号自动开通为工程师，不需要你逐人创建、发团队接入码或分发令牌。
分机安装器自动配置公共证书，网页和 CLI 使用同一个账号。

同一码代表同一身份，也可以在另一台电脑接续使用。此方式不校验姓名或密码，适用于同事互信的内网。
0.4.0 起普通用户只读已发布知识，可提交案例和报告；知识修改与发布仅管理员操作。
历史个人修订保留供历史结果追溯，不再自动影响新诊断。

## 管理员登录

开始菜单 → GWAP Debug Server →“打开数据目录”，查看 `config\bootstrap-token.txt`。
在网页登录页选择“管理员入口”，输入令牌；初始令牌有效期为一天。
进入“系统设置 → 安全与审计”，为自己签发并保存长期管理员令牌，切换后撤销初始令牌。以后继续从管理员入口登录。
旧服务器升级后继续使用原管理员令牌，不会重新生成初始账号。

管理员可停用账号。停用后，该识别码无法再次自助登录。工程师入口不能取得管理员身份。

## 三个工作入口

- **故障定位**：新建案例，选组网、连接或未知，上传GW/AP日志，开始诊断；报告按类别模板生成，保留交互问答。
  新案例默认同意使用配置的模型端点，可关闭；历史关闭记录不会被升级开启。
- **知识库**：按问题类别和用途查看知识；“已定位案例/已确认报告”保存管理员认可的共享资料。
  管理员可在AI整理助手选择整个Skill文件夹，核对每份文件的阅读进度、分类、依赖和变更差异，通过对话纠偏。
  支持UTF-8文本及脚本，每次最多64个文件、每个1MiB、合计8MiB；不支持的文件会明确提示。
  会话、分段阅读记录与草稿保存在服务器，可暂停并继续；中断的发布需要重新核对确认。
  点击“确认并发布”即审批，向量与图谱构建成功后全员生效；失败时保留原知识。
  已有知识也可以直接在助手中按标题查找、解释或提出修改。历史资料只做归类建议，不自动改原文。
- **系统设置**：普通用户选择自己的预设模型；管理员管理模型、索引、账号和审计。

同一诊断固定其启动时的知识与模板；新发布用于新诊断。选择“未知”会跨类查找并建议分类，需人工决定是否采纳。
没有对应类别模板时使用组网默认模板。报告里的异常设备时间轨迹继续保留，页面独立事件时间线入口已移除。

## 从0.3.3升级与回退

**不需要卸载0.3.3，停止服务器并备份后直接覆盖安装0.4.0。**

1. 使用原来安装、运行服务器的同一个 Windows 账号；这是按当前用户安装的程序。
2. 在旧服务器窗口按 `Ctrl+C`，等待停止完成。安装器不会自动关闭正在运行的服务器。
3. 开始菜单 → GWAP Debug Server →“备份服务器（先停止服务器）”，等待 `Backup verified`，保留备份和0.3.3安装包。
4. 运行 `GWAP-Debug-Server-Setup-0.4.0-x64.exe`，安装器会替换程序目录。
5. 双击桌面“GWAP 服务器”，首次启动自动迁移数据库到0022，等待 `READY` 后再让分机接入。
6. 使用原管理员令牌登录，检查案例和知识；到“系统设置 → 模型与索引”重建向量索引，等待成功。

原端口（包括自行改成的18081）、账号、证书、模型配置和数据目录沿用。
默认数据目录为 `%LOCALAPPDATA%\GWAPDebugServer`；如果原来设置了 `GWAP_SERVER_DATA_ROOT`，继续保留该变量和原目录。
切换 Windows 账号会改变默认程序、数据目录，不应作为覆盖升级方式。
新版分机不需要安装平台运行时；已有0.3.3连接器可继续连接。先升级服务器，再开始新的诊断。
回退必须同时恢复升级前业务备份与匹配的旧程序，不能让旧程序直接读取新版数据库。

## 数据和备份

数据默认位于 `%LOCALAPPDATA%\GWAPDebugServer`，知识、案例、附件、配置和证书都在这里。不要删除。
启动错误见 `logs\script-server.log`。

先停止服务器，再从开始菜单运行“备份服务器（先停止服务器）”。看到 `Backup verified` 后，备份位于数据目录的 `backups`。完成后重新启动。
建议每天使用结束后备份，并保留当前 EXE；不会自动执行定时备份。程序更新或卸载不会删除数据目录。

## 接续旧脚本的数据

旧数据仍在旧仓库的 `artifacts\lan\server-data`。先停止旧服务器并备份。
在 Windows“编辑账户的环境变量”中新建用户变量 `GWAP_SERVER_DATA_ROOT`，值填旧 `server-data` 的完整路径。
注销并重新登录 Windows 后再启动桌面快捷方式，即可沿用原目录。不要直接搬动目录，已有配置包含绝对路径。
