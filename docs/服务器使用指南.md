# 服务器使用指南

本次 0.5.2 内网专用安装包已包含 Python、完整 Embedding/Reranker、HTTPS 网关、服务器地址及指定的六文件组网 Skill。

## 安装和启动

1. 如果旧服务器正在运行，先按 `Ctrl+C` 停止；已有业务数据先备份。
2. 双击 `GWAP-Debug-Server-Setup-0.5.2-x64.exe` 安装。升级首次启动会迁移数据库，请等待 `READY`。
3. 双击桌面“GWAP 服务器”，等待 `READY`。首次地址已预置，之后沿用保存的配置。
4. 使用期间保持窗口打开，并关闭电脑自动睡眠；停止时按 `Ctrl+C` 等待退出。

安装包不会修改 Windows 网卡的 IP、子网掩码或网关。首次安装默认 HTTPS 端口为 `8443`；升级沿用已保存的端口。

### 上传知识时报 Embedding 输入过长

0.3.3 原安装包遇到较长 Markdown 时，可能报 `input ... is too large ... physical batch size`。
0.4.0 已包含这项修复。升级后在网页“系统设置 → 模型与索引”重建向量索引，等待任务成功，再检查此前的草稿。
如果失败的上传没有留下文档，再重新上传；已有文档无需重复上传。

### 放行 HTTPS 端口

如分机无法访问，在管理员 PowerShell 中放行端口：

```powershell
New-NetFirewallRule -DisplayName "GWAP HTTPS" -Direction Inbound -Action Allow -Protocol TCP -LocalPort 8443 -Profile Domain,Private -RemoteAddress LocalSubnet
```

该规则允许同一子网；其他网段需另行放行。已有规则时无需重复添加。

## 同事接入

把配套的分机 ZIP 发给同事。服务器先保持运行，同事安装时输入“一位小写字母＋八位数字”的个人识别码即可。
未注册的新识别码自动开通为工程师，不需要你逐人创建、发团队接入码或分发令牌。
分机安装器自动配置公共证书，网页和 CLI 使用同一个账号。

同一码代表同一身份，也可以在另一台电脑接续使用。此方式不校验姓名或密码，适用于同事互信的内网。
0.5.0 普通用户可管理自己的案例与知识草稿，修改共享知识需提交审核；管理员和专家负责共享发布与必读 Skill。
历史个人修订保留供历史结果追溯，不再自动影响新诊断。

## 管理员登录

开始菜单 → GWAP Debug Server →“打开数据目录”，查看 `config\bootstrap-token.txt`。
在网页登录页选择“管理员入口”，输入令牌。0.5.1 新安装的初始令牌有效期为七天；0.5.0 及更早签发的初始令牌仍按原来的一天到期，升级不会延长旧令牌有效期。这项源码行为不能单独证明某台服务器的登录失败原因，仍需结合实际令牌来源和错误信息判断。
进入“系统设置 → 安全与审计”，为自己签发并保存长期管理员令牌，切换后撤销初始令牌。以后继续从管理员入口登录。
旧服务器升级后继续使用原管理员令牌，不会重新生成初始账号。

如果已经无法登录，先停止服务器，在开始菜单 → GWAP Debug Server →“恢复管理员访问（先停止服务器）”。
它只为当前数据目录中已有、启用的管理员签发临时令牌，不删除数据库，不修改账号角色或其他有效令牌。它会拒绝仍在运行的服务器、多个管理员但未指定账号、仍可用的恢复令牌，以及属于其他账号的恢复令牌；过期、已撤销或未登记的旧恢复文件只会在本机核验后删除并更换。
然后打开数据目录，读取 `config\admin-recovery-token.txt`，重新启动服务器，从“管理员入口”登录。
恢复令牌有效期七天；登录后在安全与审计签发并保存个人管理员令牌，再撤销临时令牌。
若有多个管理员，工具会要求在安装目录运行 `"Recover Administrator Access.bat" --username 管理员用户名`。

管理员可停用账号。停用后，该识别码无法再次自助登录。工程师入口不能取得管理员身份。

### 专家角色与登录

管理员在“系统设置 → 安全与审计”将现有用户角色改为 EXPERT。专家继续使用原识别码，
配套 0.5.0 分机已兼容专家登录与原有凭据复用。新识别码只创建 ENGINEER，用户不能自行晋升。
ADMIN 和停用账号不能使用识别码及分机的一次性网页登录入口；管理员继续使用管理员令牌。

专家可以管理知识、必读 Skill、故障类别、共享诊断模型、重建索引和查看审计。
停用账号、修改角色、签发/重置他人凭据，以及全局 Embedding/Reranker/GGUF 配置仅管理员可操作。

## 工作入口

- **故障定位**：新建案例，选择组网、连接、未知或管理员/专家新增的类别，上传日志并开始诊断。
  新案例默认同意使用选定的模型，可关闭；历史关闭记录保持原值。保留报告、交互问答和结果提交。
- **知识库**：所有用户可查看已发布 Skill、Markdown、共享案例和报告；普通用户管理自己的知识草稿，
  上传案例、Wiki Markdown，使用 AI 案例提炼，并提交共享知识的修改/删除或 Skill 修改建议。
  共享内容经管理员或专家审核、成功构建索引后生效；普通用户不能直接改必读 Skill。
- **知识库管理**（仅管理员、专家）：直接管理必读 Skill、知识、类别、模板、索引及提交审批。
  AI 整理助手可读取整个 Skill 文件夹，列出文件用途、位置、依赖和合并/替换差异，支持多轮纠偏。
  整理助手每次最多 64 个 UTF-8 文件、单个 1MiB、合计 8MiB；不支持的文件会明确提示。
  审核用户提交时也可多轮对话修正，保存原稿、差异和审核记录，点击确认即发布审批。
  文档、向量和图谱成功构建后同时切换；失败保留原发布内容，中断后按保存状态恢复。
- **系统设置**：所有用户可添加自己的诊断 API、选择供自己诊断/问答/AI 提炼统一使用的模型。
  支持有效 HTTP(S) Base URL（包括公司内网），无需端点白名单。管理员/专家新增模型默认共享，
  也可设为私人；普通用户模型仅自己可见。个人选择优先，否则跟随共享默认；API Key 不向他人显示。
  管理员设置全局 Embedding/Reranker/GGUF，管理员及专家按权限查看安全审计。

新类别缺少专属 Skill 时提示并使用通用 Skill；连通用 Skill 也没有时仍可按日志证据诊断，
界面显著说明没有使用 Skill。

### 内置组网 Skill

0.5.0 遗漏了组网 Skill 打包；0.5.1 本地修复包包含 `hilink-diag.zip` 原包及完整六文件目录。
开始菜单 → GWAP Debug Server →“查看内置组网 Skill”可打开原始文件。
首次使用空知识库时自动备份并排队导入，后台完成向量及图谱后，六个文件一起生效，并绑定包内报告格式。
网页“知识库管理”显示初始化进度。导入使用内置 Embedding，不调用诊断大模型；已有外部 Embedding 配置时需在知识维护中确认后导入。
若升级实例已有知识、草稿、历史发布或删除记录，自动初始化会保留它们；可将随包文件夹交给 AI 整理助手核对合并差异后发布。
如果要按已确认方案清空旧知识及 Skill，请由管理员在“知识库管理”的知识维护中选择重置，检查六文件预览后确认。
此操作保留案例和报告；已有知识库不会因覆盖安装而自动清空。
后续重启和覆盖升级不会重置人工修改，也不会补回已删除的默认 Skill。所有业务数据仍保存在原数据目录。

### 慢模型等待

0.5.0 单次 Chat 请求默认等待 **15 分钟**；网页同步 AI 请求、CLI 平台长工具和新建 AI 后台任务
允许等待 **2 小时**。综合诊断继续使用原有 3 小时推理总预算、4 小时作业上限。
任务仍可取消，失败会保留原因；不要因模型排队而反复点击提交。

旧 `.env` 或模型配置中原默认 `300` 秒按新默认处理（通常为 `900` 秒），其他自定义超时保持原值。
管理员可在模型高级配置调整单个模型等待时间，也可调整服务器环境文件的 `LLM_TIMEOUT_SECONDS` 后重启。

### 查看模型任务进度

0.5.2 的诊断、问答、日志筛查、AI 提炼/整理、审核修正、Markdown 归类、候选补丁及 Chat 连接测试，
会显示当前阶段、实际完成的文件/分段或核验数量，以及约完成和约剩余的工作比例。
综合诊断依次显示收集日志、检索知识、全文阅读 Skill、多轮推理核验、综合结论、校验保存六步。
模型响应慢时显示“等待模型响应”和已等待时长；百分比按已完成步骤估算，不代表剩余时间，等待本身不会推动进度。

任务和进度由服务器保存；同一浏览器标签页刷新可恢复正在查看的任务，临时断网时保留上次确认的进度。
失败、取消、暂停和等待人工核对分别显示。AI 一轮整理完成不表示已发布；知识仍需人工核对确认。
新增的审核对话、提炼对话、Chat 连接测试及候选补丁任务不会自动重跑；检查原因后可手动重试。
候选补丁使用个人选定的诊断模型，仅供查看和复制，不自动修改代码。

自定义更长的模型等待仍受作业总上限约束。已入队任务保留创建时记录的上限，重新提交才使用新上限。
平台不能改变公司模型网关自身的超时、限流或 500 错误；更长等待也不保证模型输出满足结构要求。

同一诊断固定其启动时的知识与模板；新发布用于新诊断。选择“未知”会跨类查找并建议分类，需人工决定是否采纳。
没有对应类别模板时使用组网默认模板。报告里的异常设备时间轨迹继续保留，页面独立事件时间线入口已移除。

## 从 0.3.3 / 0.4.0 / 0.5.0 / 0.5.1 升级与回退

**不需要卸载旧版。停止服务器并备份后，在同一 Windows 账号下覆盖安装 0.5.2。**

1. 使用原来安装、运行服务器的同一个 Windows 账号；这是按当前用户安装的程序。
2. 在旧服务器窗口按 `Ctrl+C`，等待停止完成。安装器不会自动关闭正在运行的服务器。
3. 开始菜单 → GWAP Debug Server →“备份服务器（先停止服务器）”，等待 `Backup verified`，保留备份和原版本安装包。
4. 运行 `GWAP-Debug-Server-Setup-0.5.2-x64.exe`，安装器会替换程序目录。
5. 双击桌面“GWAP 服务器”，首次启动自动迁移数据库到 0025，等待 `READY` 后再让分机接入。
6. 使用仍有效的原管理员令牌登录；已过期时使用上述本机恢复入口。检查案例和知识，等待新增组网 Skill 初始化完成。

原端口（包括自行改成的18081）、账号、证书、模型配置和数据目录沿用。
默认数据目录为 `%LOCALAPPDATA%\GWAPDebugServer`；如果原来设置了 `GWAP_SERVER_DATA_ROOT`，继续保留该变量和原目录。
切换 Windows 账号会改变默认程序、数据目录，不应作为覆盖升级方式。
新版分机不需要安装平台运行时。先升级服务器，再完整解压配套 0.5.0 分机包并运行 Install.bat，
用原识别码更新客户端；专家身份支持与新的 CLI 等待设置需要新版分机文件。
已经使用 0.5.0 分机的电脑无需为这次 0.5.2 服务器更新重新安装分机。
回退必须同时恢复升级前业务备份与匹配的旧程序，不能让旧程序直接读取新版数据库。

## 数据和备份

数据默认位于 `%LOCALAPPDATA%\GWAPDebugServer`，知识、案例、附件、配置和证书都在这里。不要删除。
启动错误见 `logs\script-server.log`。

先停止服务器，再从开始菜单运行“备份服务器（先停止服务器）”。看到 `Backup verified` 后，备份位于数据目录的 `backups`。完成后重新启动。
建议每天使用结束后备份，并保留当前 EXE；不会自动执行定时备份。程序更新或卸载不会删除数据目录。

## 接续旧脚本的数据

旧数据仍在旧仓库的 `artifacts\lan\server-data`。先停止旧服务器并备份。
在 Windows“编辑账户的环境变量”中新建用户变量 `GWAP_SERVER_DATA_ROOT`，值填旧 `server-data` 的完整路径。
注销并重新登录 Windows 后再启动桌面快捷方式，即可沿用原目录。不要直接搬动目录，已有配置包含绝对路径。
